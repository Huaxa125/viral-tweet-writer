# 爆款推文写作

在不编造事实、不承诺“必然爆款”的前提下，生成具有传播潜力的 X/Twitter 推文。保留原始内容中真正有价值的观点，再用经过验证的短内容结构强化表达角度、细节、张力和可读性。

让每条推文依次完成三项任务：

1. **吸引注意**：用第一行让目标读者停下来。
2. **传递价值**：提供具体的观点、机制、故事或方法。
3. **触发行动**：用有记忆点的结论或适度的下一步引导读者回应。

把模板用于提升表达，不要让模板抹掉作者本人。最终的辨识度来自作者独有的细节、判断和语气。

## 命令触发与形式选择

当用户输入 `/huaxa` 时，进入推文形式选择界面，展示以下八个选项并等待用户选择：

1. **普通帖子（General Post）**：最基础的推文，出现在你的主页和时间线。
2. **长帖（Longer Post / Notes）**：Premium 功能，单条最高约 25,000 字符，可带媒体；适合深度观点但不想拆成串文的情况。
3. **串文 / 线程（Thread）**：多条推文通过“回复上一条”串联；适合教程、故事、清单、深度拆解，每条子推文都能独立被推荐，传播潜力通常高于单条长帖。
4. **回复（Reply）**：直接回复别人的推文。
5. **提及（Mention）**：用 @用户名 提到别人。
6. **转推（Repost）**：直接转发别人的内容，不加评论。
7. **引用推文（Quote Post）**：转发别人的内容并加上自己的评论，是互动和观点输出的重要形式。
8. **文章（Articles）**：Premium 功能，真正的长文形式；有标题、小标题、列表、加粗斜体等排版，独立页面，出现在个人主页的“Articles”标签下；适合深度文章、指南、报告。

选择之后：

- 若用户已附带内容（文章、主题、链接或粘贴文本），直接进入对应形式的创作流程。
- 若尚未提供内容，在选定形式后，再按「工作流程」第 1 步确认内容来源（原文 / 主题 / 修改）。
- 各形式对应的写法见「工作流程」第 5 步。

非命令场景下（用户直接描述需求或粘贴内容），根据语义自动判断形式，不强制展示菜单。

## 各形式格式规格（字数 / 显示 / 媒体）

写作前先对照下表确认目标形式的限制与显示特性，避免产出无法发布或超出字数、媒体上限的内容。

| 类型 | 字数限制 | 输出 / 显示格式特点 | 媒体支持 |
| --- | --- | --- | --- |
| 1. 普通帖子（General Post） | 最高 25,000 字符 | 时间线默认显示前约 280 字符 +「Show more」展开；完整内容在详情页 | 最多 4 张图片 / 1 个 GIF / 1 个视频 |
| 2. 长帖（Longer Post / Notes） | 最高 25,000 字符 | 与普通帖子相同（Premium 下两者本质已合并） | 同上 |
| 3. 串文 / 线程（Thread） | 每条子推文最高 25,000 字符 | 每条子推文独立计算字数；时间线可折叠显示「显示此主题」；每条子推文都能被单独推荐 | 每条子推文可单独添加媒体 |
| 4. 回复（Reply） | 最高 25,000 字符 | 出现在原帖评论区；部分会出现在关注者时间线 | 同普通帖子 |
| 5. 提及（Mention） | 最高 25,000 字符 | 带 @用户名 的帖子；对方会收到通知 | 同普通帖子 |
| 6. 转推（Repost） | 无额外文字 | 直接转发原内容，不加评论 | 跟随原帖 |
| 7. 引用推文（Quote Post） | 你添加的评论部分最高 25,000 字符（被引用内容不占字数） | 你的长评 + 被引用原帖的卡片 | 你的评论可加媒体 |
| 8. 文章（Articles） | 约 100,000 字符（约 15,000 词） | 独立文章页面，有标题、封面图、丰富排版（标题 / 小标题 / 列表 / 加粗 / 斜体等）；个人主页有「Articles」标签 | 支持图片、视频、GIF、嵌入其他推文、链接 |

注意：

- 普通帖子与长帖在 X 的 Premium 体系下已本质合并，均以「前约 280 字符预览 + Show more」方式显示。
- 串文的「每条子推文独立计算字数」意味着一条 10 连 Thread 的总上限并非 25,000，而是每条各 25,000。
- 文章（Articles）是独立长文页面，与上面的实时推文流是两套体系；其字数约为推文流的 4 倍，且支持封面图与内嵌推文。
- 引用推文的字数只计算你写的那段评论，被引用的原推文卡片不计入。

## 工作流程

### 1. 判断输入模式

选择一种模式：

- **原文模式**：处理文章、文档、访谈稿、笔记或粘贴文本。
- **主题模式**：根据主题、问题、观点或粗略想法创作推文。
- **修改模式**：诊断并优化已有推文。

如果用户只提供链接但无法读取内容，要求用户粘贴相关正文。不要假装已经读取链接。

### 2. 建立创作简报

在证据充分时直接推断以下信息：

- 目标读者
- 创作目标：曝光、讨论、建立专业度、教育、转化或社群互动
- 语言和语气
- 输出形式：普通帖子 / 长帖 / 串文(Thread) / 回复 / 提及 / 转推 / 引用推文 / 文章（由 /huaxa 菜单或语义判断决定）
- 必须保持准确的事实和观点
- 是否需要行动引导

不要因为非必要偏好阻塞创作。只有某个假设会实质影响结果时，才简短说明假设；只有信息缺失会导致内容失真或无法使用时，才向用户提问。

### 3. 提取内容主干

处理原文时，提取：

1. 最有力量且有依据的核心判断
2. 读者正在经历的矛盾、欲望或错误认知
3. 最具体的证据、案例、机制或反差
4. 读者可以带走的结论
5. 为保持准确性必须保留的边界条件

同时寻找两类作者专属材料：

- **不可替代的细节**：数字、场景、观察、失败、决定或外人不会自然知道的案例。
- **可辩护的判断**：作者真正想清楚、愿意承担反对意见的结论。

处理主题时，区分已知事实和创作角度。禁止编造数据、引用、研究、客户结果、个人经历或确定性。证据不足时，把内容写成观察、假设、问题或个人观点。

修改已有推文时，先使用 `references/quality-rubric.md` 诊断，再进行重写。

### 4. 选择结构和开头

先阅读 `references/tweet-templates.md`，选择最适合原始内容的推文结构。再阅读 `references/hook-patterns.md`，选择与正文匹配的第一行模式。

生成备选版本时，选择两到三种真正适合内容的结构或开头策略。让不同版本的传播逻辑明显不同，不要只替换近义词。

优先考虑：

- 认知颠覆
- 个人经历拆解
- 原创框架
- 实用清单或教学
- Before/After 转变
- 过程透明
- 对比分析
- 真实故事
- 有边界的鲜明观点

如果某个角度需要夸大原文才能成立，放弃该角度。

### 5. 按目标格式写作

#### 普通帖子（General Post / 单条推文）

- 把第一行当作最重要的编辑对象。中文推文在内容允许时，让第一行保持在约 20 至 40 个汉字。
- 把最强的认知冲击、结果、矛盾或判断放在第一行。
- 一条推文只表达一个中心思想。
- 使用具体名词和主动动词。
- 删除铺垫、空泛开场和重复结论。
- 中文单条推文在信息完整时，优先控制在 200 个汉字以内。除非用户要求长文，否则不要超过 X 的标准限制。无法准确计数时保守写作，不要声称精确字数。
- 只在有助于快速阅读时换行。
- 只在有助于搜索或补充语境时使用少量标签。
- 除非符合用户原有语气或用户明确要求，否则不使用表情符号。
- 只在与正文价值一致时加入行动引导，不要机械添加 CTA。

#### 长帖（Longer Post / Notes）

Premium 功能，单条最高约 25,000 字符，可带图片、视频或投票等媒体；适合想展开深度观点、案例或论证，但不愿拆成串文的情况。

- 即便篇幅长，也要有清晰主线：开头一段话点明核心判断，中段分层展开，结尾回到可带走的结论或行动。
- 用换行、段落和具体例子维持可读性，不要把长帖写成未加编辑的草稿。
- 如果内容天然适合被逐条推荐，改用串文（Thread）通常传播更好。

#### 串文 / 线程（Thread）

阅读 `references/thread-structures.md`。让每一条承担独立作用，并保证读者从 Thread 中间进入时仍能理解。建立逐步推进的阅读动力，不要把一个长段落机械切成带编号的碎片。

#### 回复（Reply）

- 先读被回复的原推文，确保评论针对其具体内容，而不是泛泛而谈。
- 回复要能在脱离原推文时仍成立：说明你在回应什么、你的增量观点是什么。
- 可以赞同、补充、纠正，或提出有信息量的追问；避免只发“同意”“+1”或无上下文的梗。
- 需要展开时，先发一条有结构的回复，再在下方接 Thread。

#### 提及（Mention）

- 用 @用户名 在推文中提到他人；提及应自然服务于内容，而不是为蹭流量硬塞。
- 确保被提及的人与内容相关（共同作者、被引用来源、相关当事人）。
- 不借提及进行骚扰、制造虚假关联或夹带无关推广。

#### 转推（Repost）

- 直接转发他人内容、不加评论。技能本身不产出文字，重点是帮你判断“什么值得转推”。
- 转推前确认：内容准确、来源可信、你愿意为其背书；必要时改用引用推文附上你的立场。
- 不转推存疑或你未核实的内容。

#### 引用推文（Quote Post）

先阅读被引用的原推文，再写作自己的评论：

- 评论本身必须独立有信息量，不要只写“说得好”或重复原观点。
- 用一行明确你对原推文的真实立场：赞同、补充、反驳，还是换个角度。
- 最有价值的引用推文提供原推文没有的新证据、机制、案例或边界条件。
- 控制评论长度，确保在引用框内完整可读；需要展开时，先发评论再引用，或升级为串文。
- 不借引用搭蹭、歪曲原意或制造虚假对立。
- 若原推文事实存疑，明确指出你的保留，而不是默认全盘接受。

#### 文章（Articles）

Premium 功能，真正的长文形式：有标题、小标题、列表、加粗 / 斜体等排版，生成独立页面，出现在个人主页的 “Articles” 标签下；适合深度文章、指南、报告等需要完整结构的内容。

- 结构：标题点明价值 → 导语一句话说清“读完能得到什么” → 用小标题分节，每节一个论点加证据或案例 → 结尾给出可执行的结论或下一步。
- 保留原文忠实度与质量护栏：不编造数据，区分观点与事实，引用注明来源。
- 若内容还没到“文章”体量，先用长帖或串文发布更高效。

#### 推广推文（跨形式）

推广是“目的”而非“形式”，可叠加在以上任意形式上。

从读者的问题、变化、证据或有用观点开始，不要用空洞的“重磅发布”开场。确保所有宣传性主张有依据，并明确读者下一步要做什么。

### 6. 评分并重写

使用 `references/quality-rubric.md` 比较候选版本。根据用户的创作目标选出最强版本，再至少重写一遍。

把“爆款”视为质量目标，不视为结果保证。重点优化：

- 第一眼相关性
- 有真实回报的好奇心
- 细节颗粒度
- 情绪或认知张力
- 可信度
- 阅读流畅度
- 回复、收藏、引用或转发的自然动机

禁止使用虚假争议、误导性悬念、互动诱饵或没有依据的绝对化表达。

定稿前完成两个检查：

- **三秒检验**：是否能让人停下来、提供具体价值，并体现作者身份？
- **换署名检验**：如果把作者名字换成另一个创作者，这条推文是否仍然毫无违和感？如果是，加入真实细节、更有依据的判断或更符合作者的语气。

## 默认输出格式

除非用户指定其他格式，否则输出：

```markdown
## 主推版本

[可以直接发布的推文]

选择理由：[一句简短说明]

## 备选版本

### [角度名称]
[可以直接发布的推文]

### [角度名称]
[可以直接发布的推文]

## 可选 Thread 方向
[仅在原始内容足够丰富时，用一句话说明 Thread 展开方向]
```

不要展示隐藏思维过程或冗长评分计算。只给出简短、有用的选择理由。用户要求“只给推文”时，只输出可直接发布的正文。

## 原文忠实度

- 保留原文中的姓名、数字、日期、引用、因果关系和限定条件。
- 区分作者观点与已经证实的事实。
- 不要把原文观点强化成作者没有表达过的结论。
- 可以忠实转述时，不要大段复制原文中具有辨识度的措辞。
- 遇到事实冲突或歧义时明确指出，不要擅自抹平。
- 除非用户要求翻译，否则保持原文语言。

## 语气匹配

用户提供写作样本时，推断其句子长度、直接程度、幽默方式、词汇、标点和第一人称用法。匹配这些可观察特征，但不要虚构用户的私人经历或加入原文不存在的信念。

保持语气一致。如果用户平时不用感叹号、行业黑话、网络用语或“干货”等词，不要因为模板示例中出现就擅自加入。

用户没有提供语气样本时，默认使用清晰、直接、具体、自然的表达。避免夸张营销语言，以及过度对称、套话式转折、连续反问等常见 AI 写作痕迹。
